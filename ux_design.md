# LLM Chat — UX Spec (Android, on-device, offline)

> Living spec. Updated 2026-11-15 to match the code on `feature/model-settings`: layered llama.cpp settings, per-model settings, About & licenses, context fitting, chronological message list. Items marked **(planned)** are on the roadmap at the end and not built yet.

App name **LLM Chat**, Android package `com.rdfindustries.llmchat`, URL scheme `llmchat`.

## Platform and runtime notes (binding)
- Target: Android APK / dev build on a Pixel 9 Pro XL (about 16 GB RAM). `llama.rn` is a native module and does not run in Expo Go. On web, show one full-screen notice: "On-device inference requires the Android app". No other web support is needed.
- No accounts, no network calls, no backend. All persistence uses `expo-sqlite`. Model files live in `FileSystem.documentDirectory + 'models/'`.
- Libraries:
  - `llama.rn` for inference
  - `expo-document-picker`, `expo-file-system` (copying files, free space), `expo-device` (`Device.totalMemory`)
  - `expo-keep-awake`, `expo-clipboard`, `expo-sharing`, `expo-haptics`
  - `react-native-drawer-layout`, `@shopify/flash-list` (v2), `@react-native-community/slider`
  - Markdown: `mdast-util-from-markdown` + GFM (`micromark-extension-gfm`) parse to an AST, drawn by `components/chat/Markdown.tsx`; `prismjs` for code highlighting.
  - `react-native-paper`, `@expo-google-fonts/inter`, `@expo-google-fonts/jetbrains-mono`
  - Icons: MaterialCommunityIcons only, never emoji.
- `llama.rn` is pinned to an exact version (`0.13.0-rc.11`, bundling llama.cpp b12292). Update it deliberately and rerun `yarn licenses`.

## Local data model (expo-sqlite, created in `lib/db.ts` on first launch)

**settings** — key TEXT PK, value TEXT (JSON). Keys:
- `themeMode`: 'dark' | 'light' | 'system'; default 'dark'
- `defaultSystemPrompt`; default "You are a helpful, concise assistant."
- `globalParams`: ParamSet JSON, the "Model settings for all chats" layer. (Legacy `defaultParams` from older builds is migrated on first read; values equal to the app defaults are dropped.)
- `lastSessionId`
- `lastModelId`

**models**
- id TEXT PK (uuid)
- displayName TEXT
- fileName TEXT
- filePath TEXT (absolute path in documentDirectory/models)
- fileSizeBytes INTEGER
- quantization TEXT NULL (for example Q4_K_M)
- architecture TEXT NULL
- parameterLabel TEXT NULL (for example 8B)
- detectedTemplate TEXT NULL: raw `tokenizer.chat_template` present → 'auto-available'; else null
- templateOverride TEXT: 'auto' | 'chatml' | 'llama3' | 'gemma' | 'mistral' | 'phi' | 'zephyr' | 'vicuna' | 'alpaca' | 'raw'; default 'auto'
- trainedContext INTEGER NULL
- fileParams TEXT NULL: ParamSet JSON of the recommended settings stored in the GGUF (`general.sampling.*`); `'{}'` once read and empty; null means not read yet
- paramsOverride TEXT NULL: ParamSet JSON, this model's own settings
- addedAt INTEGER

**sessions**
- id TEXT PK
- title TEXT; default 'New chat', auto-set from the first 40 chars of the first user message
- modelId TEXT NULL, FK models ON DELETE SET NULL
- systemPromptOverride TEXT NULL: null means use the global default
- paramsOverride TEXT NULL: ParamSet JSON, this chat's own settings (only the keys set at this level)
- createdAt INTEGER
- updatedAt INTEGER (indexed DESC)

**messages**
- id TEXT PK
- sessionId TEXT, FK sessions ON DELETE CASCADE, indexed
- role TEXT: 'user' | 'assistant'
- content TEXT (the answer only)
- reasoning TEXT NULL: the model's thinking, kept apart from the answer
- thinkingMs INTEGER NULL: time from the first thinking token to the start of the answer
- modelName TEXT NULL
- tokenCount INTEGER NULL
- tokensPerSec REAL NULL
- stopped INTEGER: 0 or 1, set when the user stopped generation
- createdAt INTEGER

**messages_fts** — FTS5 virtual table (content, sessionId UNINDEXED, messageId UNINDEXED), kept in sync by triggers on insert, update and delete of messages.

**prompt_presets**
- id TEXT PK
- name TEXT UNIQUE
- content TEXT
- createdAt INTEGER

**ParamSet** = a flat map of llama.rn parameter names to values (`{temperature: 1.0, top_k: 20, enable_thinking: true, …}`). Only keys explicitly set at a level are stored. Older builds' camelCase keys (`topP`, `maxTokens`, `contextLength`, …) are mapped on read.

### Settings layers
Effective settings are resolved per reply; later layers win:

| # | Layer | Stored in | Edited in |
|---|---|---|---|
| 1 | App defaults | `APP_DEFAULTS` in `lib/params.ts` | — |
| 2 | Settings for all chats | `settings.globalParams` | Settings → Model settings for all chats |
| 3 | Model file recommendations | `models.fileParams` | read-only, shown on the model's settings page |
| 4 | This model | `models.paramsOverride` | Settings → Settings per model, or Models → ⋮ → Settings… |
| 5 | This chat | `sessions.paramsOverride` | Chat settings (⚙ in the chat) |

App defaults:

| Key | Default |
|---|---|
| temperature | 0.7 |
| top_p | 0.9 |
| top_k | 40 |
| min_p | 0.05 |
| penalty_repeat | 1.1 |
| n_predict | 1024 |
| n_ctx | 4096 |
| n_threads | 4 (the number of fast cores on Tensor G4; the first app version used 6) |

The resolved set is split into **load** settings (passed to `initLlama`: `n_ctx`, `n_threads`, `n_batch`, `n_gpu_layers`, `flash_attn_type`, `cache_type_k/v`, `use_mmap`, `chat_template`, …) and **completion** settings (passed to `completion`). Each resolved value remembers which layer it came from, so the editor can say "from model file", "from all chats", etc.

Reserved keys that the app controls and the editor refuses: `model`, `prompt`, `messages`, `jinja`, `emit_partial_completion`, `embedding`, `vocab_only`, `is_model_asset`, `use_progress_callback`, `media_paths`.

## Inference behaviour (`lib/llama.ts`, ModelContext)

**ModelContext state and actions**
- State: `loadedModelId`, `status` ('idle' | 'loading' | 'ready' | 'error'), `error`, `isGenerating`.
- Actions: `loadModel(model, loadParams)` → `Promise<boolean>`, `unload()`. Loads are serialized; a failed load clears the loaded state. If a memory check fails while another model is loaded, status stays 'ready'.
- `lib/llama.ts` tracks the in-flight completion; releasing a context first stops and awaits it. `getLoadedSignature()` identifies the load settings of the current context.

**Loading**
- `initLlama({use_mlock: false, ...loadSettings, model: filePath})`.
- Release any previous context first.
- Before init, if `fileSizeBytes > 0.6 * Device.totalMemory`, show the error: "This model (X GB) is likely too large for this phone's memory. Try a smaller quantization like Q4_K_M or a model of 8B parameters or fewer."
- If init throws, show: "Couldn't load this file. It may not be a valid GGUF model or may be corrupted." plus the native message in a collapsible "Details" area.

**Templates**
- `templateOverride === 'auto'` and the GGUF has `tokenizer.chat_template`: call `context.completion({messages, jinja: true, ...})` so llama.rn applies the model's own template.
- Otherwise (auto with no template, or a manual choice): build the prompt string with the matching formatter in `lib/templates.ts` and pass `prompt` plus that template's `stop` strings.
- Auto with no embedded template falls back to ChatML and shows a one-time snackbar: "No template in file — using ChatML. Change it in Model Manager."

**Messages and sampling**
- The messages sent are `[system (effective system prompt, plus today's date when that setting is on; omitted if empty), ...the visible path up to the message being answered]`.
- **Continue** (footer `play-outline` button and long-press "Continue", on the last reply when it was stopped or cut off): the chat is formatted up to the assistant turn (jinja via `getFormattedChat` with the generation prompt, or the manual template), then the partial reply is appended verbatim (`lib/continuation.ts`: thinking re-opened with the model's own tags if it was cut off mid-thought) and completed as a raw prompt with the template's stop strings. The new text is added to the same message; token count adds up, speed is the new run's. Footer shows `· stopped` (user) or `· cut off` (hit `n_predict` or a full context).
- All resolved completion settings are passed through to `completion()` unchanged, so any llama.rn option works (including `chat_template_kwargs`-style options such as `enable_thinking`).
- User `stop` strings are merged with the template's stop strings.
- `n_predict` is capped at half the loaded context; `n_predict ≤ 0` means "half the context".
- **Context fitting** (`lib/contextWindow.ts`): before each reply, the oldest non-system messages are dropped until prompt + reply fit in `n_ctx` (8 tokens overhead per message, 16-token margin). The system prompt and the latest message are always kept, and kept history never starts on an assistant turn. When messages are dropped, a snackbar says so; nothing is deleted from the database.

**Streaming and stats**
- The partial-token callback appends to the in-progress assistant bubble.
- The result's `timings.predicted_per_second` is stored as `tokensPerSec`, and `timings.predicted_n` as `tokenCount`.

**Context and model changes**
- Before each reply, `prepareModel(model, session)` re-reads the model and session, reads the file's recommended settings once if needed, and resolves the layers. If the load-settings signature differs from the loaded context, or the session's model differs from `loadedModelId`, the model reloads first (loading banner shown).
- **Thinking** is separated from the answer while streaming. With a jinja template, `reasoning_format` defaults to `auto` and llama.rn reports `reasoning_content` / `content` on every token; otherwise (manual templates, unrecognised formats, or no thinking found) `lib/thinking.ts` splits a leading `<think>…</think>` / `<thinking>` / `[THINK]` block, including blocks opened by the template (only the closing tag in the output). `reasoning_format: none` shows the raw output.
- **Stop** calls `stopCompletion()` immediately. A stopped reply is saved with `stopped = 1`; an empty stopped reply is not saved.
- `activateKeepAwakeAsync('gen')` runs when generation starts; `deactivateKeepAwake('gen')` runs on finish, stop or error.
- On app start, if `lastModelId` exists, auto-load it in the background.

### 1. Chat (app/index.tsx) — first screen
**Purpose:** full-screen conversation with the local model.

**Top bar** (56dp, surface colour, hairline bottom border):

- Copy (both roles).
- "Edit & resend" (user messages only).
- "Regenerate" (last assistant message only).

**Edit & resend**

**Regenerate**
- Generates a new version of the last reply from the same history (the user message is not duplicated). The old reply is hidden while the new one streams and stays available in the switcher. If the new reply is stopped before producing anything, the old one shows again. Sending, regenerating and switching models are blocked while a reply is generating.

### 3. Search (app/search.tsx)
- Header with an autofocused search TextInput.
- Queries `messages_fts MATCH ?` (prefix query `term*`), debounced 250 ms, limit 100, joined to the session title.
- Result rows:
  - Session title (titleSmall).
  - A snippet using FTS5 `snippet()` with the matched term in brand colour and bold.
  - Role and date caption.
- Tap: save the session as `lastSessionId`, then pop back to Chat, which reloads it on focus. Scrolling to and highlighting the matched message is **(planned)**.
- Queries go through `buildFtsQuery()`: each word is quoted (so punctuation can't break FTS5 syntax) and the last word gets a prefix `*`.
- Empty query: hint text "Search across all your chats".
- No results: "No matches for ‘term’".

### 4. Model Manager (app/models.tsx)
Stack header: "Models", with a "Help" icon button on the right that pushes Help.

**Storage card** (tinted block): "Library: N models · X.X GB used · Y.Y GB free" (from `getFreeDiskStorageAsync`) and "Device RAM: 16 GB".

**Primary button "Add GGUF model"**
1. Open `DocumentPicker.getDocumentAsync({type: '*/*', copyToCacheDirectory: false})`.
2. Validate: the name ends with `.gguf` (case-insensitive), else show the error "Not a GGUF file. Only .gguf models are supported."
3. Check free space against size, else show "Not enough storage to import (needs X GB)."
3a. **Format check** (`lib/ggufHeader.ts`, "Checking name…"): read the GGUF header (metadata and tensor list, usually a few MB) and list tensor types the bundled llama.cpp doesn't have, plus PQ2_0/PTQ1_0 in the file name (PrismML's own packings).
   - The header is read from the picked file before copying when Android allows reading it in parts (files picked from phone storage). Files from the Downloads provider can't be, so they're checked right after copying.
   - Not a GGUF, or a truncated header: snackbar "Can't import name: reason." and nothing is kept.
   - Unsupported formats: dialog "This model may not load" naming the formats; for PQ2_0/PTQ1_0 it suggests the Q2_0 download. Before copying: "Import anyway" / "Cancel". After copying: "Keep anyway" / "Remove". Not dismissable by tapping outside.
4. Copy to `documentDirectory/models/<uuid>-<fileName>` with a progress dialog: indeterminate bar, "Importing 4.9 GB… keep the app open", and a Cancel button.
5. Read metadata via `loadLlamaModelInfo(path)`: `general.name`, `general.architecture`, `general.file_type`, `general.size_label`, `<arch>.context_length`, `tokenizer.chat_template`.
6. Quantization comes from the file name (`parseQuantFromFilename`: a quant name standing alone, so `PQ2_0` isn't read as `Q2_0`; includes PQ2_0, PTQ1_0, TQ1_0/TQ2_0, IQ*, Q*_K_XL, MXFP4), falling back to the header's `general.file_type`. Labels saved by older versions are corrected when the Models screen opens.
7. Read the file's recommended settings (`general.sampling.*`) into `fileParams`.
8. If metadata reading or anything else fails, delete the copy and show: "This file isn't a readable GGUF model."
9. On success, dialog "Delete the original?" naming the file and its size: "Keep" / "Delete" (red; tapping outside = Keep). Delete removes the picked `content://` document through the new File API (`DocumentsContract.deleteDocument`). Snackbar "Model added. Original deleted." or, when the provider refuses, "Model added, but the original couldn't be deleted. Delete name in the Files app."

**Model list** (cards, one per model)
- displayName (titleMedium).
- Chips in mono: quant, parameter label, size (for example `4.92 GB`), architecture.
- Template line: "Template: Auto (from file)" or "Template: ChatML (manual)".
- Memory hint chip:
  - Green "Fits" when size ≤ 40% RAM.
  - Amber "Tight" at 40–60%.
  - Red "Too large" above 60%; Load still attempts after a confirm.
- Actions:
  - Primary "Load", or a "Loaded" badge with a check when current. Loading shows an inline spinner and "Loading…".
  - Overflow menu: "Settings…" (pushes that model's settings page), "Chat template…" (radio dialog: Auto, ChatML, Llama 3, Gemma, Mistral, Phi, Zephyr, Vicuna, Alpaca, Raw/none), "Rename", "Remove".
  - Remove: confirm "Remove model and delete its file from app storage?" This unloads it if loaded, deletes the file, deletes the row, and sessions using it get modelId null.
- Load: if no session is generating, load the model and set it as the active session's model.

**States:** an empty state matching the Chat no-model card; an error band for load failures with Retry.

### 5b. Settings editor (components/params/ParamEditor.tsx)
Shared by Settings, Model settings and Chat settings. Props: the overrides at this level, the inherited resolved values, `onChange`.
- **Toolbar:** "Add setting" and "Paste flags".
- **Rows**, one per setting set at this level, by kind:
  - bool → switch; select → segmented buttons; number/int → slider plus numeric input; string/JSON → text input (JSON validated).
  - Each row has a label, help text, a remove ✕, "reloads model" on load settings, and a "Without this: <value> (from <layer>)" note.
- **Inherited (N)** collapsible list of values from lower layers with their source; tapping one copies it here as an override.
- **Add setting dialog:** searchable list grouped as Sampling, Repetition, Thinking, Output, Model loading, Advanced (~45 entries from `lib/paramCatalog.ts`), plus **Custom…** for any llama.rn parameter name (`/^[a-z_][a-z0-9_]*$/i`, not reserved) and a typed value.
- **Paste flags dialog:** accepts a llama.cpp command line (e.g. a model card's `llama-cli … --temp 1.0 --top-p 0.95 --presence-penalty 1.0 -c 32768 --chat-template-kwargs '{"enable_thinking":true}'`), with a live preview of what will be applied, invalid values and unknown flags. `-m`, `-p` and similar are ignored; `-c 0` is skipped.

### 5c. About (app/settings/about.tsx)
- Card: app name, version (expo-constants), llama.cpp build number and commit (llama.rn `BuildInfo`), and "Runs language models entirely on this phone. Chats, settings and model files never leave the device."
- **Open-source licenses:** searchable FlashList from `constants/licenses.json`, in sections "On-device inference (native code)", "Fonts", "JavaScript packages". Tap an entry to expand its project link and full license text (selectable, mono). Packages without a license file show their license name and link.

### 6. Presets (app/settings/presets.tsx)
- List of presets: name plus a 2-line content preview.
- FAB "New preset".
- Tap a preset to open an edit dialog (name and content).
- Swipe or overflow menu to delete, with a confirm.
- Empty state with one tap-to-add suggestion card per starter preset: "Concise assistant", "Code reviewer", "Writing editor". Each card shows its content prefilled.

### 7. Help (app/help.tsx)
Static sections as Paper List.Accordion items:
1. **Supported format:** GGUF only (llama.cpp). Other formats (safetensors, .bin, PyTorch, MLC, ONNX) must be converted or downloaded as GGUF.
2. **Which quantization:** On a Pixel 9 Pro XL (~16 GB RAM), Q4_K_M is the best balance and Q5_K_M is slightly better quality, for 3B–8B models. Approximate file sizes: 3B Q4_K_M ≈ 2 GB, 7–8B Q4_K_M ≈ 4.5–5 GB, 8B Q5_K_M ≈ 5.7 GB. Avoid models over ~9 GB; larger context lengths use more memory.
3. **Where to find models:** Hugging Face (search "GGUF"), bartowski, TheBloke, lmstudio-community, unsloth. Good starters: Llama 3.1/3.2, Qwen 2.5, Gemma 2, Phi-3.5, Mistral 7B.
4. **Copying files to the phone:** USB cable to the Downloads folder (File Transfer mode), Android Files app, or downloading directly on the phone in a browser. Then use Models → Add GGUF model. The app copies the file into its own storage and then offers to delete the original to save space.
5. **Chat templates:** Auto reads the template from the file. If replies look garbled or never stop, set the matching template in Models.
6. **Model settings (llama.cpp):** the five layers, Add setting / Custom… / Paste flags, and that "reloads model" settings apply before the next reply.
7. **Performance tips:** threads = number of fast cores (4 on a Pixel 9). Keep context at 4096 unless needed. The first load is slower.

<design_direction>
**Audience and moment:** one technical user running local models on their own Pixel, often for long sessions, frequently at night. The app should feel quiet, precise and tool-like: a well-made terminal companion, not a consumer chatbot.

**First screen:** the Chat screen of the last session. The conversation fills the screen. The composer and send/stop button sit at the bottom in thumb reach, and the model name in the slim top bar confirms what is running. On an empty chat, the model name is the largest element, with suggestion chips just above the composer.

**First-run content:** described under Chat empty states — the "Add a model" focal card on a tinted block, then the model name plus suggestion chips. Presets has starter suggestion cards.
